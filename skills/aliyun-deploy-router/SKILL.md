# 阿里云部署路由

把用户的“帮我上线”落实为适合项目的部署路径和经过验证的结果。你是协调入口；具体云操作交给经过核验的部署 Skill 或官方工具。用用户使用的语言解释，不要求新手先知道 ECS、OSS 等产品名。

## 从项目和已有状态开始

- 确认目标项目，遵守其 AGENTS.md，先读 README、依赖清单、构建/启动配置及已有部署记录。不要把当前目录默认当成目标，除非上下文支持。
- 区分静态站点、需要服务端运行的应用、后台任务；检查数据库、上传文件持久化、环境变量名称、端口、健康检查。React/Next.js 等框架名本身不足以决定托管方式。
- 检查已有 `.appmanager/`、`.qianwenai-deploy/` 等记录；保留现有部署归属和资源 ID。更新已有部署优先使用原工具，避免创建重复收费资源。
- 只列出缺失的配置项，不输出密钥值，不向用户索要聊天中的 AccessKey。复用已有登录，缺少授权时引导官方登录或本地配置。
- 在现有环境内先做可行的构建/启动检查。标明哪些检查未能执行，不为预检盲目升级全局工具。

## 选择并调用一个执行入口

读 [references/routes.md](references/routes.md)，给出推荐方案、理由、需要的服务和未确定项。用户明确指定的云产品或 Skill 优先；只在不兼容时解释并调整。

1. 查看当前可用/已安装 Skills，再核验候选上游最新文档、支持范围、依赖和实际安装路径。首次使用或更新后运行本包 `scripts/check_install.py`，检查本包完整性；读 [references/known-issues.md](references/known-issues.md)，按实际环境检查相关已知问题。
2. 读被选中 Skill 的完整 SKILL.md 及本次相关引用；按其流程执行。只说“我会调用”不算完成路由。没有专用调用工具时可直接按其文件执行。
3. 缺少 Skill 时，在用户授权的任务范围内使用环境的 skill-installer（若可用），仅安装选中的 Skill；先检查上游来源及安装脚本。若环境限制或必要权限缺失，清楚说明阻碍。不要假装已经安装或调用。
4. 安装或更新后验证真实目录和链接可解析，完整 SKILL.md、引用文件、执行脚本均可读；核对实际版本。安装器返回成功不代表可用。不要自动更新全部 Skills 或覆盖用户修改。
5. 路由最多经过一层专用部署 Skill。下游再次返回本入口时停止递归，直接处理缺失能力。搜索/诊断工具可以辅助，但不并行驱动多个部署器修改同一资源。

先完成可审阅的配置及报价，再处理必要的费用确认。已有授权可复用；创建收费资源、扩大费用或更换目标资源必须在授权范围内。提供计费周期、所含资源和估价遗漏，无法获取报价时不要编造。既有授权不足时只问阻塞执行的选择，并解释原因。

## 部署与自动排错

- 按选中 Skill 执行部署，记录阶段、版本、资源 ID、区域和退出状态；日志中去除秘密和个人信息。
- 排错默认覆盖发现、安装、授权、构建、部署、验收各阶段，不需要用户另说“查 issues”。授权、账单和配额类问题不能通过反复修改代码解决。
- 发生错误时主动读 [references/issue-repair.md](references/issue-repair.md)，搜索相关 GitHub issues，不让用户自己去搜。
- 先读本地日志定位失败层：项目、构建工具、部署 Skill、CLI、云 API 或网络。按该层选择仓库，不能把整个 Skills 集合中的反馈都归到某个部署 Skill。
- 每次修复都应有原因、最小改动和针对性验证。同一故障最多进行三次有新证据的修复尝试；每次创建/重试前查询资源实际状态，超时不能当作资源未创建。
- 确认方案不适用才换路线；复用或明确处理已有资源，禁止用多次创建服务器来试错。删除资源和数据必须符合已有授权，不将“清理”默认为可删除原有服务。

## 验收与交付

部署工具返回 success 只是一个信号。验证应用实际启动、公网 URL、关键静态资源与一条代表性功能链路；需要持久化时核验存储配置，并仅在适合的测试环境验证重启后数据。不要对生产环境做破坏性测试。

明确区分临时试用链接与正式域名/HTTPS 已完成。需要正式中国大陆网站上线时，查询当前官方域名、备案和访问要求，并报告尚未完成的条件。

简短交付：
- 选中了什么 Skill、使用什么服务、为什么。
- URL、实际通过的检查、尚未通过或未测试的项。
- 如发生错误：原因、引用的 issue/PR、采用的修复和验证结果；无匹配 issue 也如实说明。
- 现存资源、费用口径、更新方法，以及如何停止计费/释放资源（区分停止应用、停机、释放，不承诺停机即零费用）。

只有实测成功才说“已上线”。受账号、账单、区域配额或外部服务阻塞时，保留进度，报告明确的下一步和仍在计费的资源，不无限重试。
